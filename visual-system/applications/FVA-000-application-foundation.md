# FVA-000 — Facework Application Foundation

## Authority boundary

This program begins from the current Facework Visual System and Identity
Program. Earlier sites, decks, guides, prototypes, and token files are evidence
of lineage only. They may reveal a requirement; they may not silently establish
an aesthetic decision.

The governing sources are FVS-000 through FVS-900 and FVI-001 through FVI-400.
When a source conflicts with those documents, the canonical specification wins.

## Application idea — the open ledger

Facework applications behave like an **open ledger of attention**: claims,
evidence, state, and lineage share a visible field. The result is not archival
nostalgia or software chrome. It is a contemporary knowledge instrument whose
construction remains inspectable.

Five behaviors make the direction recognizable without a logo:

1. **Declared datum.** A strong reading edge organizes every field.
2. **Open interval.** Important counterparts retain space between them rather
   than collapsing into a centered block.
3. **Evidence adjacency.** Claims sit near source, status, and limitation.
4. **Variable density.** Quiet thresholds lead into dense working fields.
5. **Precise interruption.** A rule, semantic signal, or axis shift marks a real
   change in state.

## Typography

- **Identity:** Register, supplied only as canonical vector artwork.
- **Structural:** Berkeley Mono when licensed; JetBrains Mono or platform mono
  as the portable implementation.
- **Reading:** Inter or an equivalent durable neutral sans. System fallbacks are
  `Helvetica Neue`, `Arial`, then `sans-serif`.

The reading voice is intentionally sans serif. Serif editorial styling from the
first application pass is not part of this foundation.

## Color

Paper and Field are the two base conditions from FVS-600. Color appears only
when a semantic state is present. Clarity is the dominant signal in the
reference implementations because the applications chiefly expose available,
explained structure. Flow, Resonance, Boundary, and Entropy are reserved for
their named states.

## Composition

The base screen grid is 12 columns above 960 px, six columns from 640–959 px,
and four columns below 640 px. Applications transform rather than shrink:
metadata rails become inline prefaces, bilateral comparisons become sequences,
and diagrams gain structured text alternatives.

Corners are square. Containers are introduced only for state, boundary, or
interaction. Large display language is brief; sustained reading remains 50–75
characters per line.

## Motion

Motion preserves origin and consequence. Exchange Resolve is used only at a
true threshold. Interface transitions use opacity and short translation within
the FVS-800 timing system. Reduced motion is a complete static expression.

## Universal release tests

Every reference artifact must pass:

- visible purpose, status, version, and lineage;
- usable monochrome expression;
- accessible reading or focus order;
- non-color state signaling;
- appropriate scale or distance test;
- durable, editable source;
- visual inspection in its intended medium.

## Explicit exclusions

The application system does not inherit generic cards, ornamental serif display,
ochre as a universal brand accent, decorative butterflies, rounded SaaS chrome,
marketing-funnel composition, or motion without state meaning.
